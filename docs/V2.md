# Trade Assistant V2

V2 turns the app from an option pricer with a journal into a position intelligence system:
stock long and short, long calls and puts, one set of accounting rules, and analysis that
says how much evidence there is and how often similar setups worked before. It stays
advisory only. Nothing in V2 places, changes or cancels an order, and the Robinhood
connection stays read-only market data.

Everything V2 adds lives beside the classic app: the classic `/api` routes and screens work
as before, and the new routes are under `/v2`.

## Feature flags

Each V2 area can be switched off in `.env` without touching the rest of the app.

| Flag | Default | What it switches |
| --- | --- | --- |
| `FEATURE_UNIFIED_POSITIONS` | on | Positions screen and `/v2/positions` |
| `FEATURE_TREND_ENGINE_V2` | on once built | Analyze screen, `/v2/trend`, `/v2/analysis` |
| `FEATURE_PORTFOLIO_RISK` | on once built | Portfolio screen, `/v2/portfolio` |
| `FEATURE_SIGNAL_CALIBRATION` | on once built | Live pattern evidence and calibration |
| `FEATURE_OPTIONS_BACKTEST` | off | Option backtests: needs historical option prices, which no connected source provides |

Values: `1`, `true`, `yes`, `on` or `0`, `false`, `no`, `off`. A switched-off area answers
404 with a message naming the flag, and its button is hidden. `GET /v2/features` and
`GET /api/status` report the flags in force.

## Database migrations

The database is SQLite, created by `db.py`. V2 changes it through numbered migrations in
`schema_v2.py`, recorded in a `schema_migrations` table. Each runs once, inside a
transaction, when the app opens the database; a failure rolls that migration back and
stops the app rather than leaving a half-changed database.

Alembic was considered and not used: the app has no ORM, one local SQLite file per user and
no server to migrate, so a forty-line runner with plain SQL is easier to read and has no
extra dependency. Rules:

- Never edit a migration that has shipped. Add a new one.
- A migration that moves data must leave the old tables readable, so the classic screens keep working.
- `Database.schema_version()` returns the highest version applied; `/api/status` reports it.

Back up `data/trade_assistant.db` before updating if you want a way back: an older version of
the app ignores the new tables but cannot undo them.

## Unified positions (Sprint 1)

### Tables (migration 1)

- `positions`: one row per idea. `instrument_type` STOCK, OPTION (OPTION_SPREAD reserved),
  `direction` LONG or SHORT, `status` PLANNED, OPEN, PARTIALLY_CLOSED, CLOSED or CANCELLED.
  `quantity` is the planned size (shares, or contracts), `multiplier` is 1 for stock and 100
  for an equity option. The plan: `thesis`, `setup_type`, `intended_horizon` (trading days),
  `invalidation_price` (a price of the underlying stock), `target_1`, `target_2`,
  `risk_amount`, `initial_risk_per_unit`. The accounting columns (`open_quantity`,
  `average_entry_price`, `average_exit_price`, `realized_pnl`, `fees`, `opened_at`,
  `closed_at`, `status`) are a cache rebuilt from the executions after every change.
  `legacy_trade_id` links a position that mirrors a classic option-journal entry.
- `option_contracts`: the option leg of a position (type, strike, expiration, OCC symbol,
  multiplier, ratio). One leg for now; the key allows more for spreads later.
- `executions`: every fill. `side` BUY, SELL, SELL_SHORT or BUY_TO_COVER, `quantity`,
  `price` (per share; per share of the contract for options), `fees`, `executed_at`,
  `source` MANUAL, ROBINHOOD or IMPORT.
- `position_snapshots`: what the market looked like when the position was planned, entered,
  exited or reviewed: prices of the stock, SPY, QQQ and VIX; RSI, MACD, averages, ADX, ATR,
  volume ratio; swing structure, trend state, relative strength, scores and market regime;
  for options, implied volatility, IV rank, Greeks, bid, ask and days to expiration. Each
  records `signal_engine_version`, `data_timestamp`, `data_source` and `bar_status`
  (whether the last daily bar was complete), with everything else in `raw_json`.

### Accounting rules (`positions.py`)

Executions are the record; everything else is worked out from them.

- A LONG position opens with BUY and closes with SELL. A SHORT position opens with
  SELL_SHORT (or SELL) and closes with BUY_TO_COVER (or BUY).
- Average cost. Opening fills move the average cost of what is open; closing fills realize
  `sign × (exit − average cost) × quantity × multiplier`, with sign +1 long and −1 short.
- Fees are subtracted from realized profit when paid.
- A fill that would close more than is open, or close before anything is open, is refused.
  The whole sequence is checked, so a back-dated fill cannot break later ones.
- Options are whole contracts, and only long calls and puts for now.
- Status: PLANNED until the first fill, OPEN, PARTIALLY_CLOSED once some has been closed,
  CLOSED when nothing is open, CANCELLED only from PLANNED.
- Unrealized profit uses the current mark: the stock's last price, or the option's
  midpoint (model value when there is no two-sided quote; intrinsic value after expiration).
- R multiple: total profit divided by the initial risk, which is the entered dollars at
  risk; else `initial_risk_per_unit × size × multiplier`; else, for stock, the distance from
  the average entry to the invalidation price times the size; else, for a bought option, the
  premium paid.
- Times without a zone are New York time; a plain date means that day's 4 p.m. close; fills
  in the future are refused.

Example: short 1,000 CRWD at $250, cover 300 at $240 and 400 at $235. Open: 300 shares.
Realized: $3,000 + $6,000 = $9,000 before fees. At $243.60 the 300 open show $1,920
unrealized.

### The classic option journal

Migration 1 copies every classic journal entry into `positions` as a long call or put
(`setup_type` "option journal", `legacy_trade_id` set). After that, every change in the
journal (save, filled attempt, close, cancel) updates its mirror in the same transaction,
so the two never disagree. The journal stays the place to record those trades; the
Positions screen shows them and refuses fills for them.

### API

| Method and path | What it does |
| --- | --- |
| `GET /v2/features` | Feature flags in force |
| `GET /v2/positions?status=open\|planned\|closed\|cancelled\|all` | Positions with marks, P&L and thesis check |
| `POST /v2/positions` | Create a position, optionally with its entry fill |
| `GET /v2/positions/{id}` | One position with legs, executions, snapshots and ledger |
| `POST /v2/positions/{id}/executions` | Record a fill |
| `POST /v2/positions/{id}/plan` | Change thesis, setup, horizon, invalidation, targets, risk, notes |
| `POST /v2/positions/{id}/cancel` | Cancel a plan that never filled |
| `POST /v2/positions/{id}/snapshot` | Take a REVIEW snapshot now |

Create body:

```json
{"symbol": "CRWD", "instrument_type": "STOCK", "direction": "SHORT", "quantity": 1000,
 "thesis": "Lower highs under resistance", "setup_type": "reversal", "intended_horizon": 15,
 "invalidation_price": 265, "target_1": 230, "target_2": 215,
 "entry": {"price": 250.0, "fees": 0, "executed_at": "2026-10-01T10:05"}}
```

For a call or put add `"instrument_type": "OPTION"` and
`"option": {"option_type": "PUT", "strike": 205, "expiration": "2026-11-06"}`; the entry
price is per share of the contract.

The response includes `ledger` (open quantity, cost basis, averages, realized, fees,
initial risk), `pnl` (realized, unrealized, total, fees, r_multiple, market_value), `mark`,
`thesis_check` (INTACT, INVALIDATED, TARGET_1_REACHED, TARGET_2_REACHED, NO_INVALIDATION,
UNKNOWN) and `snapshots`.

## Versions of the logic

Results that come from an engine carry its version (`versions.py`), and snapshots store
them, so a result can be traced to the logic that produced it after the logic changes.
